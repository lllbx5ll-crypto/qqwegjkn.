# NEXBOTS Android v3.1 — مشروع أندرويد أصلي

هذا **مشروع Android Studio قابل للبناء بعد الإعداد**، وليس ملف APK مبنياً أو مختبراً على جهاز. يستخدم WebView مقيداً على `https://nexbots.pages.dev` لكي تظهر تحديثات الموقع عند إعادة فتحه، مع خدمات أندرويد أصلية.

## المزايا المضافة
- تسجيل Google من **Credential Manager**، مع إمكان اختيار حساب من حسابات الجهاز. يتم تسجيل الدخول في Firebase على موقع NEXBOTS عبر هوية Google الموثقة، لا عبر صفحة Google داخل WebView.
- فتح واتساب وتيليجرام وإنستغرام والبريد في التطبيقات الخارجية باستخدام Android Intents.
- تنزيل مشاريع NEXBOTS عبر Android DownloadManager: **شريط تقدم** ثم زر **فتح** الذي يعرض تنزيلات الهاتف، والملف محفوظ في مجلد Downloads. يستخدم طلب التنزيل رمز Firebase الخاص بالمستخدم لمراعاة الصلاحيات والشراء.
- **Firebase Cloud Messaging** للرسائل الخاصة وإعلانات المالك. إذن إشعارات Android 13+ مطلوب. Firebase قد يؤخر تسليم الإشعارات حسب الجهاز والطاقة والاتصال.
- دعم واجهة PWA ونسخ محفوظة محدودة دون اتصال. **لا تحفظ الرسائل الخاصة أو الإيصالات أو الملفات التي لم تُشاهد** تلقائياً.
- الروابط والشريط والمحتوى يتحدثون مع الموقع بعد نشر التحديث على Cloudflare. تغيير كود Android الأصلي أو أذوناته يحتاج إصدار APK جديداً.

## متطلبات لا يمكن تجاوزها
1. افتح Firebase Console، مشروع `exbots` ← Project Settings ← Add App ← Android. أدخل **Application ID:** `dev.nexbots.android`، ثم أضف **SHA-1 وSHA-256** لتوقيع التطبيق إلى المشروع. هذه الخطوة ضرورية لكي يعمل اختيار Google على جهاز حقيقي.
2. **تم دمج** `google-services.json` في `app/google-services.json` بهذه النسخة. إذا غيّرت إعداد Firebase أو أضفت SHA fingerprints، نزّل النسخة المحدثة من Firebase.
3. **تم تعبئة** Web OAuth Client ID الصحيح من ملف Firebase في `app/src/main/res/values/strings.xml`.
4. تأكد من تفعيل Google Sign-in Provider في Firebase Authentication، ومن وجود Google Play services على الهاتف.
5. انشر تحديث الموقع v3.1 على Cloudflare **قبل تجربة الإشعارات والتحميل**؛ شيفرة JavaScript الجديدة تتواصل مع الجسر الأصلي.
6. راجع ملف `SETUP_PUSH_CLOUDFLARE_AR.md` المرفق في حزمة الموقع لتفعيل خدمة إرسال الإشعارات فعلياً.

## البناء باستخدام Android Studio
- افتح المجلد الذي يحتوي `settings.gradle.kts` في Android Studio؛ واترك Gradle ينزّل الاعتمادات.
- يتطلب المشروع Android SDK API 35، Java 17، Gradle 8.9، Android Gradle Plugin 8.7.3.
- نفّذ `Build > Build APK(s)`، أو `gradle assembleDebug` مع Gradle 8.9.
- يوجد مسار بديل عبر GitHub Actions في `.github/workflows/build-debug-apk.yml`، يتطلب رفع المشروع إلى مستودعك وإضافة أسرار `FIREBASE_ANDROID_JSON_B64` و`GOOGLE_WEB_CLIENT_ID` ثم `Run workflow`؛ يظهر APK كتجهيز قابل للتحميل من Artifacts.
- debug APK للتجربة، وليس نسخة نشر Google Play. نسخة الإنتاج تحتاج توقيع release رسمي، ومراجعة سياسات المتجر، وحفظ مفتاح التوقيع بأمان.

## اختبار إلزامي قبل توزيع APK
- افتح التطبيق وسجّل الدخول بـGoogle واختر حساباً، ثم أغلق وافتح التطبيق وتأكد من حفظ الجلسة.
- افتح رابط واتساب وتيليجرام وتحقق من ظهور التطبيق المناسب لا خطأ `ERR_UNKNOWN_URL_SCHEME`.
- نزّل مشروعاً عاماً ومشروعاً يتطلب سماح شراء؛ تحقق من احترام الصلاحيات ثم فتح الملف بعد انتهاء تنزيله.
- أرسل رسالة خاصة من حساب ثانٍ والتطبيق في الخلفية، ثم جرّب إشعاراً عاماً من لوحة المالك.
- امنع إذن الإشعارات وتأكد من عدم ادعاء أن إشعاراً وصل؛ وجرّب انقطاع الإنترنت بعد فتح بعض الصفحات.

## تنبيهات
- لا يمكنني اختبار بناء APK هنا لأن Android SDK/Gradle ومعلومات Firebase الخاصة بتطبيقك غير متوفرة. **لا تعتبر الإشعارات أو تسجيل Google فعّالين قبل تنفيذ إعداداتك واختبار جهاز حقيقي**.
- لا ترسل `google-services.json` أو مفاتيح خدمة Firebase السرية داخل محادثات عامة؛ استخدم إعدادات المنصة المقصودة.


راجع أيضاً `حالة_ربط_Firebase_AR.md` لمعرفة ما تم وما يحتاج اختباراً.


## حساب موحد وتسجيل دخول مرة واحدة
- يستخدم تطبيق أندرويد وموقع NEXBOTS مشروع Firebase نفسه (`exbots`). عند استخدام حساب Google نفسه تعود هوية Firebase `uid` نفسها، ومن ثم تظهر بيانات المستخدم ومشاريعه المحفوظة على الخادم في الموقع والتطبيق.
- تسجيل الدخول الأول على أندرويد يتم بواسطة Credential Manager، ثم يُمرَّر Google ID Token بأمان إلى الموقع داخل WebView كي يُنشئ Firebase Auth جلسة. لا نفتح تسجيل Google داخل WebView.
- يحتفظ Firebase Web Auth بالجلسة في التخزين المحلي داخل التطبيق، فلا يطلب اختيار حساب Google كل مرة عند إغلاق التطبيق وفتحه، ما لم يُسجّل الخروج أو تُمسح بيانات التطبيق أو تُلغَ الجلسة.
- جلسة Chrome وجلسة WebView منفصلتان؛ توحيد الحساب والبيانات لا يعني نقل ملفات تعريف الارتباط تلقائياً بين التطبيق والمتصفح.
- تطابق SHA-1 / SHA-256 مع شهادة **النسخة المثبتة فعلياً** شرط لا غنى عنه قبل ضمان عمل تسجيل Google. نسخ debug وrelease وGoogle Play قد تستخدم شهادات مختلفة.
- تحديث ملف موقع React (نسخة الموقع المرفقة) يحتاج نشره على Cloudflare؛ تعديل Android فقط لا يغير JavaScript المباشر الذي يخدمه موقعك.

راجع `NEXBOTS_توقيع_الاختبار_وFirebase_AR.md` لتعليمات بصمات SHA الفعلية ومفتاح debug التجريبي.
