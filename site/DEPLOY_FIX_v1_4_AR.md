# NEXBOTS — تحديث v1.4 لتصحيح اختلاف الإصدارات

## المشكلة المحددة من صور الجوال
ظهر التصميم القديم ورموز بديلة رغم وجود أيقونات SVG وخطوط جديدة في سورس v1.3، ما يرجح نشر ملفات غير متطابقة أو عدم وصول التحديث كاملاً. رسالة «لم تكتمل إعدادات Firebase للخادم» يمكن أن تأتي من API أقدم بقي ضمن النشر؛ لا يمكن تأكيد حالته من صور واجهة الموقع وحدها. لا تُعلن أن Firebase يعمل حتى تنجح طلبات API واختبار رفع الصورة فعلياً.

## مميزات هذا التحديث
- تمييز واضح لنسخة الواجهة `v1.4.0` بجانب اسم NEXBOTS وفي التذييل.
- endpoint `/api/health` يعرض رقم نسخة الخادم ووجود FIREBASE_PROJECT_ID وFIREBASE_WEB_API_KEY وR2 binding من دون كشف أسرار.
- زر إعادة اتصال إذا تعذر تحميل إعدادات Firebase بدلاً من صمت الخطأ.
- تغيير خط العربية إلى Tajawal للنصوص وReadex Pro للعناوين وOutfit للإنجليزية. تعتمد خطوط Google على توفر اتصال شبكة المستخدم، وإلا يظهر خط احتياطي مناسب.
- أيقونات SVG العلامات التجارية موجودة داخل `src/lib.js`، فلا تحتاج رفع مجلد icons لكي تظهر.
- إزالة عدادات تسويقية وهمية 05+ و100% و24/7 واستبدالها بمعلومات قابلة للتحقق؛ العدد الفعلي للتصنيفات 6، والمشاريع المعتمدة من API.
- تحسين تباين الأيقونات وبطاقات الإحصائيات وتخفيف التخزين المؤقت لصفحة HTML.

## خطوات نشر مضبوطة — من دون خلط نسخ
1. احتفظ بنسخة احتياطية من مستودع GitHub.
2. افتح مجلد المستودع على الكمبيوتر، انسخ **محتويات** مجلد NEXBOTS_V1_4 إليه (وليس المجلد الخارجي)، ووافق على استبدال الملفات بنفس المسارات، خصوصاً `src/` و`server/` و`functions/` و`wrangler.toml` و`index.html`.
3. تأكد من وجود `package.json` و`wrangler.toml` و`src/App.jsx` في **جذر** مستودع GitHub، ثم Commit + Push على فرع main.
4. في Cloudflare Pages، افحص آخر Deployment وأنه مرتبط بأحدث commit وأن حالته Success.
5. افتح الموقع في تبويب خاص. يجب رؤية v1.4.0 بجوار شعار NEXBOTS. إذا لم ترَ الرقم، فالتحديث لم يصل للواجهة بعد.
6. افتح `https://nexbots.pages.dev/api/health`: يجب أن يعرض version: v1.4.0 وbucketBound: true وprojectConfigured: true وwebApiKeyConfigured: true. إذا بقي الخادم بإصدار أقدم فهناك ملف وظائف API قديم أو نشر غير مكتمل.
7. **مهم:** انشر ملف `firestore.rules` المرفق في Firebase Firestore Rules. لا تستخدم قواعد v1 القديمة التي ترفض كل عمليات الكتابة، فهي غير متوافقة مع طريقة المصادقة الجديدة.

### إن استمر خطأ Firebase بعد تطابق الإصدارين
احصل على نص `/api/health` دون إرسال رموز خاصة، ثم راجع حالة نشر قواعد Firestore. لا تنشئ Service Account Key ولا تضع أي سر في GitHub. لم يتم اختبار نشر Cloudflare الفعلي من بيئة إعداد هذا الأرشيف.
