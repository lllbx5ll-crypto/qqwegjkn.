# إعداد إشعارات NEXBOTS v3.1 (Cloudflare Pages + Firebase Cloud Messaging)

**لم يتم تفعيل الإرسال الحقيقي تلقائياً**. تحتاج خطوات الإعداد التالية بمشروعك لدى Firebase وCloudflare. هذا النظام مستقل عن قواعد Firestore الحالية ولا يحتاج إضافة أذونات عامة لقراءة رموز الأجهزة.

## 1. إعداد Firebase للمراسلة
- استخدم مشروع Firebase الحالي `exbots`.
- من Firebase Console ← Project Settings ← Cloud Messaging تأكد من تفعيل **FCM HTTP v1 API** على مشروع Google Cloud.
- أنشئ Service Account بصلاحية إرسال رسائل FCM فقط (صلاحية `Firebase Cloud Messaging API Admin` أو الدور الأدنى المدعوم للإرسال). احصل على ملف JSON الخاص به بشكل آمن.
- **لا تحفظ ملف JSON السري في مجلد `public` أو `src`، ولا ترفعه إلى GitHub.**

## 2. إعداد Cloudflare Pages
- أنشئ KV Namespace، مثلاً `nexbots-push-tokens`.
- ضمن Settings → Functions → KV namespace bindings، أضف binding باسم **`PUSH_TOKENS`** واربطه بهذا Namespace.
- ضمن Settings → Variables and Secrets أضف متغيراً **سرياً** باسم **`FCM_SERVICE_ACCOUNT_JSON`**، وضع *المحتوى الكامل* لملف حساب الخدمة (JSON). لا تضع الملف في الكود.
- تأكد أن `FIREBASE_PROJECT_ID = exbots` كما في إعدادات المنصة الحالية.
- إذا كنت تستخدم `wrangler.toml` لإدارة الربط، أضف `[[kv_namespaces]]` بالمعرّف الفعلي الذي يعرضه Cloudflare، دون معرّفات وهمية. أي إعدادات للإنتاج والمعاينة يجب أن تكون متسقة.
- انشر نسخة الموقع المعدلة (مجلد المشروع الكامل أو ملف الإصلاح في مواضعه الصحيحة) ثم أعد نشر Cloudflare Pages بعد تغيير الربط والأسرار.

## 3. طريقة الإشعارات
- عند دخول مستخدم من تطبيق أندرويد، يحصل التطبيق على FCM token ويرسله بأمان إلى `POST /api/push/register` مع Firebase ID token للمستخدم. تحفظ Cloudflare KV هذا الرمز باسم الجهاز والحساب، ولا تعيده للمستخدمين الآخرين.
- بعد نجاح `POST /api/private/threads/{id}/messages`، تحاول Cloudflare إرسال إشعار خاص للمستلم؛ لا يتم إلغاء إرسال الرسالة إذا تعطلت FCM.
- من لوحة المالك افتح **«الإشعارات العامة»**، اكتب عنوان الإعلان ومحتواه ثم أكد الإرسال. الإرسال يتم إلى موضوع FCM العام `nexbots_announcements` الذي يشترك فيه تطبيق أندرويد.
- عند تسجيل الخروج المعتاد من الموقع، يُزال تسجيل الجهاز للحساب السابق، ثم يُعاد ربطه بالحساب التالي.

## 4. تحقق قبل النشر العام
1. اختبر إرسال رسالة من حساب آخر على جهاز مُثبت عليه تطبيق أندرويد وعنده Google Play services.
2. اسمح بإشعارات التطبيق من إعدادات الجهاز.
3. أرسل إعلاناً عاماً وأعد تشغيل التطبيق للتأكد من ظهور الإشعار عند الضغط عليه.
4. تأكد من عدم وصول الإشعارات إلى الحساب السابق بعد تسجيل الخروج وتغيير الحساب.
5. إذا فشل التسجيل فتأكد من KV binding وSecret وFCM HTTP v1 وملف `google-services.json`.

## حدود مهمة
- Push يحتاج إنترنت؛ ولا يمكن وصول إشعار أثناء انقطاع الاتصال.
- قد تؤخر أنظمة البطارية الإشعارات، ولا توجد ضمانات لتسليم فوري 100%.
- البيانات المخزنة في التخزين المؤقت للعرض العام فقط، وليست نسخة كاملة من قاعدة Firestore.
- لتفادي مفاتيح خاصة في GitHub أو في الواجهة، يعتمد إرسال FCM على Cloudflare Pages Functions والخادم فقط.
