# NEXBOTS v1.3 — تحسين الخطوط، رفع صورة الحساب، الأيقونات والباقات

هذا التحديث يحافظ على مشروعك نفسه وبيانات Firebase وCloudflare R2. لا تنشئ مستودعاً أو مشروع استضافة جديداً.

**إصلاح حقيقي:** تحديثات الحساب كانت تنقل قيمة `id` المشتقة من Firestore REST إلى المستند عند حفظ صورة الحساب، فتُرفض الكتابة حسب قواعد المستخدم؛ `server/firestore.js` الآن يستبعد حقول الميتاداتا. عند فشل حفظ صورة جديدة، تُزال من R2 لمنع تكدس الملفات اليتيمة.

**تحسينات:** خطوط IBM Plex Sans Arabic وAlexandria وOutfit عبر Google Fonts، أيقونات SVG مضمّنة في حزمة JS (لا تعتمد على تحميل `public/icons` منفرداً)، Google، ألوان ذهبية للاشتراكات، عروض غنية للمميزات الموجودة فعلاً، حركات خفيفة مع احترام وضع تقليل الحركة. إذا كانت هناك مميزات قد خصصتها من لوحة المالك، لن نمحوها.

**للنشر من الجوال:** ارفع الملفات الموجودة في تحديث ZIP الصغير داخل مستودع `NEXBOTS` في `main` مع مساراتها نفسها. لا ترفع ملف ZIP نفسه كمستند؛ استبدل الملفات بعد فك الضغط. Cloudflare Pages يعيد البناء تلقائياً. افتح تبويب Deployments وتحقق من Success، ثم افتح موقعك في تبويب خاص إذا بقي كاش النسخة القديمة.

**Firebase:** هذا التحديث ليس بحاجة إلى قواعد جديدة، لكنه يفترض نشر قواعد Firestore الجديدة الخاصة بنسخة keyless v1.1 (القواعد المرفقة `firestore.rules` في النسخة الكاملة). إذا كان لديك القواعد القديمة التي تمنع الكتابة، ستفشل صورة الحساب حتى بعد إصلاح الكود.

**اختبار:** تشغيل `node --test tests/*.test.js` نجح محلياً. لم يتوفر تثبيت حزم Vite/React أو بيئة Firebase/Cloudflare الحية داخل هذه الجلسة؛ اختبار البناء والنشر والرفع الحقيقي بعد GitHub ما يزال ضرورياً.

# NEXBOTS v1.2 — إصلاح التنقل والشاشة السوداء والأيقونات

## ما تغير فعلاً

- إضافة حدّ آمن لأخطاء صفحات React، مع زر إعادة المحاولة والعودة للرئيسية بدلاً من الشاشة السوداء.
- حماية بيانات الموقع والباقات والحساب إذا كانت استجابة Firebase ناقصة، وحماية صفحات الملفات الشخصية غير الموجودة.
- استخدام تمرير متوافق مع متصفحات الجوال، وتحسين استجابة خيارات التصنيفات.
- تحديد مهلة 20 ثانية لطلبات API ورسالة عربية عند انتهاء المهلة، مع معالجة بطء بدء المصادقة.
- شعارات SVG حقيقية مضمّنة محلياً لواتساب وتيليجرام وPython وJavaScript وPHP وإنستغرام، وأيقونة Google متعددة الألوان.
- أيقونات الاشتراكات والتاج باللون الذهبي، مع الحفاظ على الطابع الأسود والبنفسجي.
- تحسين حجم الشعار داخل الموقع بصيغة WebP مع الاحتفاظ بالشعار الأصلي PNG.

## طريقة النشر بعد الإصلاح

1. إذا كنت تستخدم ملف التحديث الصغير، ارفع الملفات إلى **جذر** مستودع GitHub `NEXBOTS` مع الاحتفاظ بمسارات `src/` و`public/`.
2. استبدل الملفات القديمة التي لها الأسماء نفسها، وأضف مجلد `public/icons/` و`public/nexbots-logo.webp`.
3. نفّذ Commit على فرع `main`. Cloudflare Pages سيعيد البناء والنشر تلقائياً إذا ظل الربط التلقائي مفعلاً.
4. افتح **Cloudflare Pages → Deployments** وتأكد من نجاح آخر نشر، ثم افتح الموقع وحاول الرئيسية، الاستكشاف، الاشتراكات، الدعم، رفع المشروع، الملف الشخصي، والأقسام.
5. إذا رأيت النسخة القديمة، حدّث الصفحة تحديثاً كاملاً أو افتح الرابط في تبويب خاص.

**ملاحظة اختبارية:** تم التحقق من الصياغة ونجحت الاختبارات البرمجية المحلية، لكن لم نتمكن من تشغيل بناء Vite الكامل أو اختبار حساب Firebase الحقيقي داخل بيئة التنفيذ هذه. لا تدّعِ أنها خالية من جميع الأخطاء قبل الاختبار على النسخة المنشورة.

**قواعد Firestore:** هذا التحديث لا يغيّر `firestore.rules` أو `wrangler.toml` ولا يتطلب إنشاء مفاتيح إدارية. يجب أن تبقى قواعد v1.1 المنشورة صحيحة، وملف القواعد داخل النسخة الكاملة موجود للمرجعية فقط.

# NEXBOTS — إصلاح اتصال Firebase بدون مفتاح خدمة (v1.1)

هذه نسخة من نفس مشروع NEXBOTS الأصلي، وليست مشروعاً جديداً. تم الحفاظ على الشعار والتصميم والصفحات وربط R2 `FILES` بمساحة `nexbots-files`.

## لماذا كان الموقع يعرض «لم تكتمل إعدادات Firebase للخادم»؟

النسخة 1.0 استخدمت مفتاح Firebase Admin SDK لخادم Cloudflare Pages؛ لكن سياسة Google Cloud لمشروعك تمنع إنشاء مفاتيح حسابات الخدمة. النسخة 1.1 أزالت الحاجة إلى هذا المفتاح بالكامل:

- يتحقق خادم Pages من توقيع Firebase ID Token القادم من المستخدم.
- عند مخاطبة Firestore REST، يمرّر هوية المستخدم نفسه؛ **Firestore Security Rules** هي التي تسمح أو تمنع العمليات.
- الزائر غير المسجّل لا يستطيع الكتابة، لكنه يستطيع قراءة إعدادات الموقع العامة والمشاريع المعتمدة فقط.
- الدور `owner` مقيّد ببريد Google الموثّق `lllbx5ll@gmail.com` **وبـ UID مثبت** في `config/owner` بعد أول دخول.
- رفع الصور والملفات لا يزال يمر عبر Pages Functions إلى Cloudflare R2 الخاصة، وليس عبر Firebase Storage.

## الخطوتان الوحيدتان لتفعيل الإصلاح على مشروعك المنشور

**الأولى — تحديث قواعد Firestore:**

1. افتح Firebase Console، مشروع `exbots`، ثم **Firestore Database → Rules**.
2. استبدل محتوى القواعد القديمة **بالملف `firestore.rules` الجديد بالكامل**، ثم اضغط **Publish**.
3. لا تستخدم القواعد القديمة من v1.0؛ كانت تمنع كل عمليات الكتابة من المستخدمين، لأنها اعتمدت على Admin SDK.

**الثانية — تحديث ملفات GitHub في نفس المستودع:**

1. افتح مستودع GitHub الموجود أصلاً `lllbx5ll-crypto/NEXBOTS`، فرع `main`.
2. استبدل فقط الملفات الموجودة في أرشيف `NEXBOTS_PATCH_KEYLESS.zip` **بنفس أسمائها ومساراتها**.
3. لا ترفع ZIP نفسه كمستند داخل المستودع؛ فك ضغطه ثم حدّث الملفات.
4. بعد Commit، سيعيد Cloudflare Pages نشر الموقع آلياً من فرع `main`، باستخدام `npm run build` و`dist`.
5. لا تنشئ Worker جديداً، ولا Bucket جديداً، ولا مشروع Firebase جديداً.

**لا حاجة بعد الإصلاح لـ `FIREBASE_PRIVATE_KEY` أو `FIREBASE_CLIENT_EMAIL`.** إذا سبق وضعهما في Cloudflare، احذفهما بعد التأكد من نشر النسخة الجديدة. لا تعطل سياسة منع مفاتيح حساب الخدمة في Google Cloud.

## ما الذي بقي كما هو؟

- واجهة NEXBOTS العربية RTL ذات الألوان الأسود والبنفسجي، والشعار المعتمد.
- تسجيل Google والبروفايلات والشارات والاشتراكات اليدوية والأسعار القابلة للتعديل.
- إدارة المشاريع وقبولها أو رفضها، والشات والحدود اليومية، ولوحة المالك.
- صور المشاريع حتى 200KB، وملفات المشاريع حتى 3 MiB، والتنزيل عبر الخادم.
- ربط R2: `[[r2_buckets]] binding = "FILES"; bucket_name = "nexbots-files"`.

## اختبار سريع بعد النشر

1. افتح `https://nexbots.pages.dev/api/health`، متوقع JSON فيه `"authMode":"firebase-id-token-rules"` و`"bucketBound":true`.
2. افتح `https://nexbots.pages.dev/api/public`، يجب أن يعرض إعدادات الموقع العامة.
3. افتح الموقع وسجل دخول **حساب المالك الأساسي**. تأكد من ظهور لوحة الإدارة (وراجع Firebase `config/owner`).
4. جرّب بحساب عضو آخر: ينبغي أن يرفض رفع مشروع قبل منحه اشتراكاً.
5. امنح الحساب اشتراك Plus بمدة حقيقية؛ جرّب رفع مشروع، ثم اعتماده من لوحة المالك وتنزيله.
6. اختبر الشات والحصة اليومية من مستخدم عادي، وكذلك تفعيل التوثيق والحظر وانتهاء الاشتراك.

## حدود مهمة قبل فتح الموقع للجمهور

- **الاختبارات في هذه الحزمة اختبارات محاكاة**؛ ليست بديلاً عن اختبار قواعد Firestore في Emulator أو على نسخة تطوير مع Firebase وCloudflare الحقيقيين.
- **حظر الكلمات على مستوى API فقط** في هذه النسخة. لأن Firestore Rules الجديدة تسمح بإنشاء الرسائل المصرح بها من هوية Firebase، يمكن لمستخدم تقني الاتصال بـFirestore مباشرة وتجاوز قائمة الكلمات الممنوعة؛ لا تعتمد على هذا الحظر وحده في بيئة عامة معادية. الحظر والكتم والحصة اليومية وصلاحيات المالك لها فحوص قواعد منفصلة، لكن تحقق منها عملياً قبل الإطلاق.
- التحقق من أمان ملفات ZIP والسكربتات (البرامج الخبيثة) غير متوفر آلياً؛ استعرض المشاريع يدوياً.
- سبق أن سجّل Build في Cloudflare تنبيه `4 high severity vulnerabilities` في اعتماديات النسخة الأصلية. **لم نثبت إغلاقها**، ويلزم مراجعة `npm audit` وترقية الحزم واختبار النتيجة قبل إطلاق واسع.
- أي تعديل في Firestore Rules يحتاج اختبار نشر فعلي؛ لا يمكن الادعاء بأن الموقع خالٍ من كل خطأ دون هذا الاختبار.
- R2 مجانية ضمن الحصص؛ تجاوز الحصص قد يؤدي إلى رسوم.

## ملفات التعديل المطلوبة فقط

- `server/auth.js` — حذف OAuth بمفتاح خدمة مع إبقاء التحقق من JWT.
- `server/firestore.js` — تحويل REST للعمل بهوية Firebase للمستخدم.
- `server/api.js` — تصحيح الاستعلامات، والصلاحيات، وحصص الرسائل/التنزيل، وتمرير الهوية.
- `firestore.rules` — حماية المالك والاشتراكات والمشاريع والشات بدون Admin SDK.
- `wrangler.toml` — إضافة Firebase Web API key العامة المطلوبة للوصول غير المسجّل.
- `src/App.jsx` — عرض رسالة مفهومة وزر إعادة المحاولة بدلاً من دوامة تحميل مستمرة.
- `tests/core.test.js` و`tests/integration.test.js` — تحديث اختبارات المحاكاة لتوافق آلية المصادقة الجديدة.
- `README_AR.md` — هذا الدليل.

لا توجد أسرار خاصة ضمن هذه الملفات.

## تنبيه مهم إذا لم تعمل نافذة الدخول بحساب Google

افتح **Firebase Console → Authentication → Settings → Authorized domains** وتأكد أن نطاق موقعك `nexbots.pages.dev` مضاف. إذا لم يكن مضافاً، أضفه من اللوحة دون تغيير المفاتيح. متصفحات بعض التطبيقات قد تمنع نوافذ Google؛ عندها افتح الموقع من Chrome أو Firefox مباشرة. هذه مشكلة بيئة تسجيل الدخول وليست عدم وجود أيقونة Google.
