# تحديث NEXBOTS v2.2 — إصلاح الخاص والرفع وتحسين الصفحة

هذه **نسخة من نفس مشروع NEXBOTS**؛ تحتفظ بالشعار والألوان والبروفايلات والاشتراكات والمشاريع والشات العام والستوريات والبلاغات والحظر ولوحة المالك وعامل حذف القصص.

## الإصلاح المؤكد في الرسائل الخاصة

كان مسار `POST /api/private/threads/:id/messages` يدخل خطأً إلى معالج إنشاء المحادثة `POST /api/private/threads` بسبب شرط عام لا يفحص طول المسار. لهذا كان يقول «معرّف غير صالح» عند إرسال الرسائل أو تحديث القراءة. الإصلاح يفصل المسارين ويضيف عنواناً مستقلاً لكل محادثة: `/private/t/<threadId>`، مع التحقق من الطرفين على الخادم قبل إظهار أي رسائل.

## رفع المشاريع

- تحسين التعامل مع انقطاع الاتصال ورفض الخادم مع رسائل عربية واضحة.
- عند فقدان استجابة رفع المشروع أو الستوري، يبحث الموقع أولاً عن المستند باستخدام `submissionId` نفسه قبل أن يقترح إعادة المحاولة. لا يعد المستخدم بالنجاح إذا لم يتم التأكد.
- مسار `GET /api/upload-status/projects/<submissionId>` و`GET /api/upload-status/stories/<submissionId>` يرفض فحص العمليات التي لا تخص الحساب المسجل.
- لم نغيّر حد صور المشاريع 200KB ولا ملفات المشاريع 3MB، ولا ربط `FILES → nexbots-files`.

## ترتيب قسم الخاص والستوريات

- ستوريات المجتمع أول الصفحة.
- تحتها بحث `@username`، ثم قائمة المحادثات.
- إزالة العنوان الكبير المتكرر داخل القسم.
- فتح أي محادثة في صفحة رسائل مستقلة، مع زر رجوع والاسم والصورة وروابط الرسائل وحالة القراءة والحظر والإبلاغ.
- لا تغيير في حدود اشتراك نشر الستوري أو 24 ساعة أو 15 ثانية للفيديو.

## النشر بالترتيب

1. **Firebase:** افتح مشروع `exbots` → Firestore Database → Rules. استبدل القواعد بمحتوى ملف **`firestore.rules` من هذه الحزمة**، ثم اضغط Publish. لا تستخدم قواعد v1.x.
2. **GitHub:** فك ضغط الحزمة الكاملة، ثم انقل **محتوياتها** إلى جذر المستودع الحالي `NEXBOTS` باستبدال النسخة القديمة؛ تأكد أن `package.json` و`src` و`server` و`functions` كلها في الجذر، ثم Commit/Push إلى `main`. لا ترفع ZIP كملف داخل المستودع.
3. **Cloudflare Pages:** راجع Deployments وتأكد أن آخر نشر **Success**. فحص `https://nexbots.pages.dev/api/health` يجب أن يحتوي على `version: "v2.2.0"` و`bucketBound: true`.
4. **التجربة:** من حسابين مختلفين افتح الخاص وابحث باسم المستخدم ثم أرسل رسالة. جرّب قراءتها من الحساب الآخر، وحظر المرسل، ثم رفع مشروع بصيغة JS/ZIP وصورة JPG/PNG/WebP حقيقية.
5. **تنظيف الستوري من R2:** إن لم تفعّل عامل `cleanup` المجدول من النسخة السابقة، فلا بد من تفعيله بشكل مستقل. تحديث صفحات GitHub وحده لا يشغّل الجدولة.

لا تحتاج إنشاء حساب Google Cloud جديد أو إنشاء مفتاح خدمة أو إنشاء مساحة R2 جديدة، ولا تطلب منك هذه النسخة إرسال أي بيانات سرية.

## حدود الاختبار

- اجتازت النسخة 53 اختباراً محلياً (بما فيها طلبات API موقّعة في الاختبار، ومحاكاة Firestore وR2، وسيناريو إرسال رسالة وقراءة وحظر).
- تحققنا من صلاحية صياغة React/JSX عبر مترجم TypeScript، ومن صياغة ملفات الخادم عبر Node.
- **لم يتم إجراء بناء Vite الكامل أو اختبار العمليات على حساب Firebase وR2 الحقيقيين** لعدم إتاحة تثبيت حزم npm هنا؛ لذلك الاختبارات المحلية ليست ضماناً لغياب جميع أخطاء الإنتاج.
- إذا بقي خطأ شبكة، راجع **Cloudflare Pages → Deployments → Functions logs** في وقت حدوثه، مع إخفاء أي رموز دخول أو بيانات خاصة. لا تعاود إرسال مشروع مدفوع قبل فحص «مشاريعي».
